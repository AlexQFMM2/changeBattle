# UI Design

做任何页面、弹窗、面板或大型组件前，必须先读本文件。

ChangeBattle 的 UI 不是网页后台，也不是普通响应式网页。所有页面都先按 `640 x 320` 游戏视口设计，再通过外层 viewport 缩放适配桌面窗口和 App 横屏。640x320 是设计基准，不是最终低分辨率画布；禁止用全局 transform: scale 缩放主 viewport。

## 组件边界

- 页面只负责放组件、组织布局和派发 action。
- 组件负责真正的业务交互、内部状态和可复用 UI。
- 页面里不要内联复杂流程。背包、队伍选择、技能替换、结算列表、状态详情这类交互必须拆成组件。
- 同一种交互只能有一个组件来源。休整页和战斗页都要用背包时，应共用背包组件，而不是各写一套。
- 无论组件当前是否确定会复用，都优先写成组件；页面仅引用组件、传递数据和处理页面级跳转。
- 页面不直接写业务流程 UI。只要某段 UI 有状态、列表、选择、弹窗、滚动或交互步骤，就应优先拆成组件。

## 组件预览与假数据

- 所有组件都必须支持假数据独立显示，不能依赖真实后端、真实存档或某个页面才能看见完整样式。
- 组件假数据应覆盖主要视觉状态：普通、选中、禁用、空状态、长文本、数量变化、滚动内容、错误/不可用原因。
- 复合组件必须在组件文件或同目录文档中写清楚引用了哪些子组件。例如背包组件必须标明它引用了道具详情、当前队伍、技能替换等组件。
- 为了方便测试，项目需要维护一个组件列表文件，所有可预览组件都登记进去。
- 首页必须提供“查看组件”入口。进入后通过组件列表一页显示一个组件，用假数据查看组件本身样式。
- 组件预览页只负责读取组件列表、切换组件和提供预览画布；组件样式、假数据和状态展示由组件自身或同目录 preview 文件提供。
- 新增或重构 UI 组件时，必须同步更新组件列表和假数据预览；否则视为 UI 工作未完成。

## CSS 归属

- 每个页面、每个组件都必须有自己的独立 `.tsx` 和 `.css` 文件。
- 页面 CSS 只负责页面骨架、组件摆放和传入组件尺寸变量，不写组件内部样式。
- 组件 CSS 只负责该组件内部布局、尺寸比例、状态样式和滚动区域。
- 不允许把新页面或新组件的主要样式继续堆进全局 `styles.css`。全局文件只放真正全局的 reset、字体、根布局、基础 token。
- CSS 变量必须有所属前缀，前缀来自页面或组件名，避免互相污染。
- CSS 变量格式统一为：`--<组件或页面名字>-<组件或页面类型>-<具体变量>`。
- 页面示例：`livePage.tsx` / `livePage.css` 使用 `--live-page-width`、`--live-page-header-height`。
- 组件示例：`bagContainer.tsx` / `bagContainer.css` 使用 `--bag-container-width`、`--bag-container-list-width`。
- 组件默认尺寸写在组件自己的 CSS 里；外部页面只通过覆盖组件公开的 CSS 变量传尺寸。
- 组件内部所有尺寸必须从自己的变量或局部派生变量计算，不要让父页面直接选择组件内部 DOM class 改宽高。
- 组件被多个页面复用时，页面只能改组件公开变量，不能复制一份组件 CSS。

## 尺寸基准

- 设计基准视口：`640 x 320`。
- 页面可视区域优先保证一屏内信息密度，不按 Web 大屏卡片布局设计。
- 固定格式元素必须有稳定尺寸，例如列表行高、图标尺寸、按钮高度、HP 条高度、棋盘/队伍槽位尺寸。
- 移动端和桌面端都复用同一套比例，不用 `vw` 直接放大字体。
- 不要太依赖 `flex`、`100%`、`100vw` 这类一把梭布局。能用准确数值、固定行高、明确列宽和受控滚动区域时，优先用准确数值。

## 字体比例

字体大小以进存档后的主页 `MainMenu` / `MainMenuHome` 为基准。新增页面默认使用下面这组值：

- 页面主标题：`14px`，只用于页面顶级标题，例如休整菜单标题。
- 面板标题：`8px`，参考 `.main-favorites-panel header strong` / `.main-discovery-panel header strong`。
- 主要按钮：`8px`，参考 `.main-menu-panel button`。
- 普通列表主文本：`9px`，参考 `.main-user-panel strong`。
- 卡片标题：`7px`，参考 `.main-favorite-card strong` / `.main-discovery-card strong`。
- 辅助文本、标签、说明：`6px`，参考 `.main-user-panel small` / `.main-favorites-panel header span`。
- 极小 eyebrow：`5px`，参考 `.main-favorite-card small` / `.main-discovery-card small`。
- 数值短标签：`8px`，参考 `.main-user-panel b`。

放大字体必须有明确理由。弹窗或详情页可以把局部重点文本提升到 `10px-12px`，但不能把列表、筛选、按钮整块放大成网页字号。

## 颜色规则

- 浅色背景必须配深色文字，例如 `#fffdf5` / `#f8f4ec` 背景配 `#25332b`。
- 深色背景必须配浅色文字，例如主页深色遮罩配 `#fff` 或半透明浅色文字。
- 不允许浅底浅字、深底深字。
- 状态色只用来表达状态或选中，不用来大面积装饰。
- 禁用态可以降低 opacity，但文字仍需可读。

## 滚动条

- 滚动条必须适应当前 UI 风格，不能直接露出系统默认粗灰条。
- 小面板优先使用窄滚动条：`8px-10px`。
- 滚动条颜色应来自页面边框/面板色系，例如深绿灰 thumb + 浅米色 track。
- 列表内容应为稳定行高，滚动时不能因为 hover、标签或按钮导致行高跳动。

## 页面密度

- 左侧列表一般只放关键识别信息：图标、名字、数量或状态。
- 说明文本放右侧详情，不放进左侧列表挤高度。
- 筛选、分页、标签栏必须单行优先；内容过多时横向滚动或缩写，不要默认换两行。
- 组件内文字超出时使用省略号或内部滚动，不能撑破 `640 x 320` 布局。

## 首页组件规则

- 首页左侧推荐区复用 V1 `FavoritePokemonPanel` 与 `DiscoveryPanel`。这两个组件的 JSX 结构、CSS class、motion variants、hover/tap 动画、Reorder 行为和点击回调语义不允许改动。
- V2 只能在外层容器做数据适配，例如把 V2 图鉴搜索结果转换成 `MainMenuDexCard`，以及把卡片点击映射到 V2 `QuickDexModal`。

## 背包类 UI 规则

- 背包左侧：筛选条 + 道具列表。
- 道具列表一行只展示图标、名字、数量。
- 背包右侧：当前道具详情、说明、使用按钮。
- 点使用后右侧切换为队伍选择或技能替换流程。
- 队伍选择行必须显示图片、名字、HP 条、状态/道具和操作标签；HP 条必须有颜色填充。

## 实施检查

提交 UI 改动前至少检查：

- `640 x 320` 下文字是否重叠。
- 列表行高是否稳定。
- 滚动条是否符合页面风格。
- 浅底/深底文字对比是否正确。
- 页面是否只在组合组件，复杂交互是否已经拆到组件。
- 新增或重构的组件是否有独立假数据预览。
- 组件列表文件是否登记了该组件。
- 复合组件是否写清楚引用的子组件。
