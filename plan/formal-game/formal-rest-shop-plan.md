# Formal Rest Shop Plan

## Summary

正式休整商店后续从“双向买卖列表”调整为更像游戏内设施的店铺系统。商店只负责购买；出售回到玩家背包中处理。UI 本阶段只记录方向和约束，不把具体画面、像素位置、货架样式写死，待后续重新规划后再实现。

## Direction

- 休整页后续移除「抽奖机」入口，经济补给主入口集中到「商店」。
- 商店作为正式 GameRun 休整设施，只接正式流程金币、库存和存档。
- 训练场不接真实商店；只保留组件预览或调试入口。
- 商店负责“买入”，不再显示玩家背包出售列表。
- 出售能力集成到「我的背包」：
  - 背包中支持单选/多选出售。
  - 正在被宝可梦携带的道具不可售。
  - 不可售、0 价、系统关键道具不可售。
  - 卖价沿用 `Math.floor(cost * 0.25)`。

## Shops

商店拆成 5 个店铺，每个店铺对应一个货柜和一个商品分类：

- 药水店：恢复药、异常恢复、复活、PP 回复等。
- 树果店：树果类。
- 技能机器店：`tm:<moveId>`。
- 战斗道具店：常见携带道具、战斗道具。
- 训练道具店：糖果、努力值药、薄荷、王冠、特性道具等。

玩家通过左右箭头切换当前店铺。每次只展示一个店铺，避免一屏塞满 5 类列表。

## UI Direction

本计划不锁定最终 UI，只记录当前倾向：

- 横屏休整页适合“左侧门面 / 右侧货柜”的构图。
- 左侧可放当前店铺门面、招牌、店主或分类氛围元素。
- 右侧放当前店铺货柜。
- 货柜倾向使用游戏化货架，而不是网页表格列表。
- 当前参考方向是“两行两列”的货柜展示，列之间留出明显间距。
- 商品格不再同时塞「详情」「购买」两个按钮。
- 更自然的交互是：
  1. 选择货架商品。
  2. 在详情/交互区查看说明、价格、库存。
  3. 点击购买。
- UI 必须继续遵守 `docs/ui-design.md`：
  - 以 `640 x 320` 为设计基准。
  - 商店必须是独立组件。
  - 商店组件必须有独立 CSS 和 preview。
  - 不把复杂交互写进休整页页面本体。
  - 列表/货格尺寸稳定，不因文字、按钮、hover 导致跳动。

## Inventory And Star Chart

商品库存容量后续由星图扩展：

- 默认每个店铺 3 件商品。
- 星图节点逐步扩充到 12 件。
- 数据结构按每分类多个 slot 设计，不和 UI 单屏展示数量强绑定。
- 当库存超过单屏货柜容量时，UI 可选择：
  - 货柜分页。
  - 店铺内货架翻页。
  - 店铺内受控滚动。

具体星图节点、消耗和解锁路线待后续规划，不在本计划中写死。

## Data And Runtime Rules

- 每个休整节点拥有独立商店状态，按 `run.seed + nodeId + category` 稳定生成。
- 同一休整节点重复打开商店，商品保持不变。
- 商品购买成功后，若自动补货能力开启，则同分类补一个新商品。
- 自动补货后续应受星图能力控制；当前实现可先保持默认开启或改成能力开关，待星图规划确认。
- 买入只更新运行时 `FormalGameRunV4`。
- 卖出只更新运行时 `FormalGameRunV4`。
- 用户点击休整页「保存」时才写入正式存档。
- 交易热路径不能调用全量 `normalizeFormalRun`，避免买卖卡顿。

## Implementation Notes

后续实现建议拆成几步：

1. 休整动作入口移除「抽奖机」，保留「商店」。
2. 商店组件改成购买专用，不再内嵌背包出售区。
3. 新增店铺切换状态：当前分类、左右切换、当前选中商品。
4. 商店 UI 只依赖 `shop`、`money`、`busy` 和购买回调。
5. 背包组件增加出售模式或出售动作。
6. API 保持轻量交易路径，只 patch 背包、金币、商店和 coinLog。
7. 星图库存扩展节点确认后，再接入每类 `3-12` 的库存上限。

## Open Questions

- 五个店铺是否需要各自店主/门面素材，还是先用分类招牌和货柜完成第一版？
- 每个店铺单屏展示 4 个商品时，库存 5-12 的交互采用分页、滚动还是货架翻页？
- 自动补货是否第一版默认开启，还是等星图节点完成后再开放？
- 背包出售是作为常驻动作按钮，还是切换到“出售模式”后支持多选？
- 不同分类的货柜是否需要明显不同皮肤，还是先统一货柜样式只改招牌？
