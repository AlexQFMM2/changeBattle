# Formal Game V4 基础框架计划

## Summary

正式游戏 V4 继续沿用 V1 的游戏规则和赛程味道，但落到 V2 的新架构上：背包、AI、队伍生成器、对局偏好、休整页都使用当前 V2 系统。

实现顺序调整为：

```txt
V1 NPC/speciesRank/powerProfile/队伍资源迁移
-> V2 NPC 与队伍生成
-> 7 场正式游戏循环
-> 结算记录
-> 休整经济设施
```

第三场和第七场固定 boss 的旧规则废弃。boss 不再由 round index 决定，而由 NPC 身份决定：馆主、四天王、冠军、邪恶头领都算 boss 战。

## Core Rules

- 一整局正式游戏仍为 7 小场。
- 单打为 `6v3`，双打为 `6v4`，合作为 `6v2`。
- 难度随连胜整局增加，连胜分布为：
  - 连胜 0：菜鸟 / 一般 / 馆主 / 一般 / 一般 / 精英 / 馆主
  - 连胜 1：一般 / 精英 / 馆主 / 精英 / 馆主 / 精英 / 四天王
  - 连胜 2：精英 / 精英 / 四天王 / 精英 / 馆主 / 四天王 / 冠军
  - 连胜 >=3：精英 / 馆主 / 精英 / 四天王 / 四天王 / 四天王 / 冠军
- 冠军和邪恶头领可以在 boss 位互相替换。
- 特殊事件、任务暂不纳入本轮基础框架；训练家星图先接入第一版“多多益善”路线，只影响开局候选数量。

## NPC And Team Generation

NPC 与队伍生成是正式游戏第一优先级。这里不做一套过度复杂的全局构筑器，而是分成两条路径：

- 普通路人 NPC：随机生成，绑定战斗风格偏好和队伍偏好，作为正式游戏的变数来源。
- boss NPC：馆主、四天王、冠军、邪恶头领都从预生成队伍池中选择，和 V1 一致。

- 从 V1 引入宝可梦物种分布，并在 V2 中命名为 `speciesRank`。
- V2 数值强度使用 `powerProfile`，不照搬 V1 旧数值档命名。
- 迁移参考：
  - V1 `docs/randomPokemonRule.md`
  - V1 `data/pokemon_tiers.csv`
  - V1 `data/npc_trainers.csv`
  - V1 `data/boss_dialogues.json`
  - V1 `data/rainbow_rocket_dialogues.json`
  - V1 `data/boss_team_pools.csv`
  - V1 `data/rainbow_rocket_team_pools.csv`
  - V1 `data/boss_representatives.csv`
  - V1 `data/rainbow_rocket_representatives.csv`
- 普通路人 NPC、馆主、四天王、冠军、邪恶头领都进入 V2 NPC 模型。
- V1 NPC 基础资料、台词、立绘/头像引用、代表宝可梦和 boss 队伍池已迁入 V2 dex-core 的本地数据模块，可在 V2 QuickDex 的“训练师”分类查看。
- QuickDex 训练师分类用于验证迁移结果，支持全部、馆主、四天王、冠军、反派头目、特殊事件筛选。
- 馆主、四天王、冠军、邪恶头领已补 V2 boss 画像：战斗偏好、AI 深度、数值强度、队伍偏好和至少 12 只偏好宝可梦。
- Boss 队伍自由度低于普通 NPC：物种池主要围绕偏好宝可梦扩展；Boss 强度主要来自更高 AI 思考深度、预设队伍主题和正式数值缩放，而不是更随机的构筑。
- Boss 预制队伍矩阵已生成静态候选池：132 个 boss 训练师，每个 36 套完整 6 只队伍，覆盖 `none/gen7/gen8/gen9 * singles/doubles/coop * 3`，总计 4752 队。
- Boss 预制队伍全量数据保存在 dex-core 的 `boss-preset-teams.json`，轻量矩阵摘要进入训练师图鉴；审阅文档见 `docs/boss-trainer-preset-team-generation.md`。
- 玩家侧生成宝可梦默认不携带道具。
- NPC 队伍允许携带道具，但普通 NPC 道具按数值档位分池，低连胜不会拿满配强道具。
- 普通 NPC 可以复用 V2 队伍生成器，叠加 `speciesRank`、`powerProfile`、战斗风格偏好、队伍偏好和对局偏好过滤。
- boss NPC 使用静态预制队伍候选池；正式游戏生成阶段按模式、规则预设、神战开关、地区限制和连胜强度选择候选，并对预设数值做正式流程缩放。

正式游戏数值档位：

- 菜鸟 `rookie`：等级不超过 50，IV 总值 `0-50`，EV 总值 `0-100`，技能乱配，不带道具或只带树果。
- 一般 `normal`：等级不超过 53，IV 总值 `40-70`，EV 总值 `80-200`，保留 1-2 个合适技能，携带树果或一般强度道具。
- 精英 `elite`：等级不超过 55，IV 总值 `60-120`，EV 总值 `180-300`，全合适技能，携带一般强度道具或少量正确强道具。
- Boss/冠军 `boss/champion`：只用于正式 Boss 缩放后的高档位，最高等级 65，最高满个体、EV 总值 510，道具和主题优先沿用预设构筑；技能在完整 `pokemonSets` 接口接入前按正式档位和角色生成。

Boss 静态预设队伍中的高等级和满配数值保留给未来 Boss rush；正式 7 场流程先读取其物种、道具和主题，等级/IV/EV 按当前连胜温和缩放：

- 连胜 0：馆主缩到精英上限，不使用 90 级或满配 Boss rush 数值。
- 连胜 1：馆主保持精英上限，四天王进入 Boss 低配。
- 连胜 2：四天王、冠军/邪恶头领接近 Boss 高配。
- 连胜 >=3：冠军/邪恶头领可到 65 级、满个体、510 EV。

`gen7/gen8/gen9` 正式 NPC/AI 队友的 battle bag 必须补对应系统道具；`standard` 不补。玩家开局候选仍默认不携带道具。

正式游戏创建 7 场 round plan 时，Boss 队伍选择不再穷举生成“神战开关 * 地区组合”的静态矩阵，而是把现有 4752 队作为原始候选池，再按本次 run 固化的 `battlePreference` 做筛选：

1. 先按固定维度筛选：`trainerId`、模式（单打/双打/合作）、规则预设（`none/gen7/gen8/gen9`）。
2. 再按用户偏好扣除：`legendaryBattle=false` 时排除包含神兽/幻兽的队伍；`allowedGenerations` 只保留全部宝可梦都来自允许世代的队伍。
3. 如果筛选后仍有足够候选，使用 seed 从静态候选池中选择。
4. 如果筛选后候选不足，动态补队：继续以该 Boss 的偏好宝可梦池为主，并把神战关闭和地区偏好转成 `excludedSpeciesIds`/允许物种池传入队伍生成器。
5. 动态补队仍不足时，按同类型、同地区、通用高质量池逐级放宽，但必须写 diagnostics。
6. 静态选择或动态补出的最终队伍都必须固化到本次 `roundPlan`，读档和返回页面不得重新随机。

后续正式游戏队伍选择入口建议为：

```ts
selectBossPresetTeamForRoundV4({
  trainerId,
  mode,
  ruleSet,
  battlePreference,
  seed,
})
```

输出需要标明来源：

```ts
{
  source: "static" | "dynamic-refill",
  team,
  diagnostics,
}
```

玩家开局候选生成只读取 runGame 中固化的 `battlePreference` 快照，不追溯后续全局 profile 修改。随机池按地区、神战开关和合法形态过滤；战斗背包开关随 run 保存但不影响随机物种池。玩家普通候选只从 `speciesRank=rank4/rank5/rank6` 抽取，神战开启时 `legendary` 可进入候选池但数量受控。所有玩家开局候选默认不携带道具，闪光概率为 `1/30`。

基础 6 只候选走轻量角色配比，不做完整模板构筑：

- 1 只天气队组件。
- 1 只空间队组件。
- 2 只进攻型。
- 1 只辅助手。
- 1 只防御手。

训练家星图第一版提供“多多益善 I-IV”四个单级节点，每点亮一个节点让随机候选数量 +1。正式 run 创建时会冻结 `starChartSnapshot`，之后玩家再点星图不会影响已创建 run。本轮星图最多把随机候选从基础 6 只扩展到 10 只，新增 4 个随机位不重复保底天气/空间：

- 第 7 只：速度控制/节奏手。
- 第 8 只：干扰/场地/撒场手。
- 第 9 只：第二防御或辅助补位。
- 第 10 只：泛用攻击或队伍短板补位。

星图第一版数据挂在 `UserProfileV2`：

- `battlePoints` 保存当前 BP。
- `starChart.nodes.root_trainer_star=1` 默认点亮。
- `starter_more_choices_1/2/3/4` 分别消耗 10/12/15/20 BP。
- 首页测试模式按钮只把 BP 设置为 `99999`，不自动点亮节点。

玩家完成开局选择并点击进入游戏后，进入正式游戏中转页。中转页负责一次性准备当前 7 场：

1. 单打/双打按 7 场生成 7 个对手 NPC。
2. 合作模式先进入队友招募步骤，玩家选择本局 AI 队友偏向：进攻、防守、辅助或均衡；不选择时默认均衡。
3. 合作模式每场生成 3 个 NPC：2 个对手 + 1 个 AI 队友；整局共生成 21 个 NPC，其中 14 个对手、7 个队友。
4. 合作模式 AI 队友固定为精英等级，不参与连胜分布降级或 boss 替换；招募偏向只影响 AI profile 与队伍偏好，不改变强度等级。
5. 给所有 NPC 绑定随机战斗风格偏好，作为 AI profile 的来源之一；合作 AI 队友使用玩家招募选择的偏向。
6. 只给普通路人 NPC 绑定随机队伍偏好，例如天气队、高火力队、空间队、防守中转队等；合作 AI 队友根据招募偏向映射到相近队伍偏好。
7. 普通路人 NPC 根据队伍偏好生成队伍。
8. 馆主、四天王、冠军、邪恶头领从预生成队伍池选择队伍，不走普通随机队伍偏好。
9. 根据生成好的队伍、NPC 类型和当前连胜场次，重新分配每只宝可梦的 `powerProfile`；合作 AI 队友按精英强度生成。

连胜 >=3 仍保留两个普通 NPC，因为普通 NPC 的随机战斗风格和队伍偏好是正式游戏后期的主要变数来源。

## Formal Run Loop

正式游戏 run 先生成 7 场 round plan，再逐场创建 battle。

- 创建正式 run 时固化当前 `battlePreference`。
- 创建正式 run 时固化当前 `starChartSnapshot`。
- 根据模式确定 battle size：单打 `6v3`，双打 `6v4`，合作 `6v2`。
- 根据连胜数生成 7 场 NPC 类型分布。
- 玩家进入中转页时生成 7 场 NPC 和队伍快照；合作模式先固化玩家招募的队友偏向，再为每场生成 2 个对手快照和 1 个精英 AI 队友快照。
- 每一场从已生成的 round plan 读取对手和队伍快照。
- 胜利进入休整页，失败结束 run。
- 7 场完成后，本整局通关，连胜 +1。
- 通关后可以继续生成下一整局，也可以结算退出。

胜利进入休整页时：

- 先发放 500 金币。
- 再结算猫车费用。
- 记录金币流水。
- 更新上一局对手快照，供交换系统使用。
- 写入战斗伤害/KDA 原始记录。

猫车规则：

- 进入休整页时，如果玩家宝可梦阵亡，工厂自动复活并保留 1 HP。
- 复活 1/2/3 只分别扣除 20/30/50 金币。
- 阵亡 4 只及以上视为失败，不进入正常休整。

BP 规则：

- BP 不再和金币绑定。
- 每场胜利按 NPC 类型和当前连胜计算。
- 普通 NPC 系数为 `0.5`，馆主为 `1`，四天王为 `1.5`，冠军/邪恶头领为 `1.8`。
- 第一版公式为：

```ts
Math.round(coefficient * Math.max(1, streak + 1))
```

## Rest Facilities

休整设施挂在正式 run 的当前休整状态上，所有消费和收入都必须写金币流水。

- 抽奖：免费领取只能一次；抽奖起价 10 金币；同一次休整中每抽一次价格 +5；不再分池；保留同样赠送。入口为左侧公共栏第二行第一格。
- 商店：每次休整刷新；每种类型道具上架 2 种；支持购买；支持出售背包道具，出售价格为获得价格的 1/4；花 50 金币重新刷新商店。入口为左侧公共栏第二行第二格。
- 交换：每次休整可以和上一局对手交换一次。免费交换不带道具且换来半血；50 金币交换不带道具且满血；200 金币交换带道具且满血满状态。Mega 石和 Z 纯晶不随交换带走。入口为左侧公共栏第一行第二格。
- 战斗道具使用次数：树果统一 1-2 次；抽奖抽到的战斗道具 2-4 次；商店购买的战斗道具 3-6 次；背包道具名称旁显示剩余使用次数。
- 遗传老爷爷：教授遗传来源技能，200 金币一次。入口为左侧公告栏第三行第一格。
- 教授老奶奶：教授教授来源技能，200 金币一次。入口为左侧公告栏第三行第二格。
- 能力值/技能随机：基础 10 金币，每锁定一项 +5；个体、努力值、技能三套费用互不影响。
- 预览对局：点击问号解锁下一局宝可梦，费用为 10/15/30/50 金币。

## Records And Settlement

正式游戏需要新增两类记录，供最终结算和回放使用。

金币流水记录：

- 所有金币收入和支出都必须记录。
- 至少记录时间/阶段、来源类型、金额、余额、关联宝可梦/道具/NPC。
- 用于最终结算、经济回放和后续天赋/返利系统。

战斗伤害记录：

- 用于最终 KDA、伤害造成、伤害承受统计。
- 至少记录造成伤害、承受伤害、击倒、倒下、参与助攻候选、来源 battleId/roundIndex。
- 参考 V1 结算页 used pokemon 数据结构，但按 V2 battle snapshot/log 重新沉淀。

## Testing Direction

文档整理本身只新增 plan/checklist，不需要跑类型检查。后续实现必须补纯函数测试：

- 连胜分布生成 7 场顺序正确。
- boss 判定只由 NPC 类型决定。
- 单打/双打/合作 battle size 分别为 `6v3`、`6v4`、`6v2`。
- 玩家生成队伍无携带道具，NPC 生成队伍可携带道具。
- 胜利奖励、猫车扣费、BP 结算、金币流水记录正确。
- 抽奖/商店/交换/教授/遗传/随机费用余额不足时失败且不改 run。
- 战斗伤害记录能汇总 KDA、伤害造成、伤害承受。

## Assumptions

- V1 规则作为设计基准，但 V2 以当前背包、AI、队伍生成器、对局偏好架构为事实入口。
- 正式游戏优先顺序为：NPC 与队伍生成 -> 7 场游戏循环 -> 结算记录 -> 休整经济设施。
- 第三场/第七场固定 boss 的规则废弃，后续文档和代码都不再依赖 round index 判断 boss。
- 完整 boss 队伍不会一次性重制完成，先迁移可用资源，再逐步补强。
- 物种分布与数值强度的详细规则分别见 `docs/pokemon-species-rank-distribution.md` 与 `docs/pokemon-power-profile-distribution.md`。
